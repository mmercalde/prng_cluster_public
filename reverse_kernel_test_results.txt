WHAT THIS FILE IS
  A record of a reverse-kernel run across 20 PRNG variants. Every single row
  reads "Forward=0, Reverse=0, BOTH ZERO". There are no positive rows anywhere
  in the file.

WHY IT IS NOT EVIDENCE OF ANYTHING
  All results were BOTH ZERO, and NO POSITIVE CONTROL was established. Nothing
  in this run demonstrated that the detector could produce a non-zero result
  when a non-zero result was the correct answer. A run that returns zero
  everywhere is consistent with two completely different worlds:

      (a) the kernels are correct and there genuinely were no survivors;
      (b) the kernels, the harness, the residues, the thresholds or the launch
          path were broken in a way that returns zero unconditionally.

  This file cannot distinguish them. That is the definition of a VACUOUS
  DETECTOR: a check that was not checking, presenting as a result.

PROHIBITED FROM CITATION UNDER VIR-2
  docs/VERIFICATION_INTEGRITY_STANDARD.md, VIR-2: a vacuous-capable detector
  requires execution proof, a CLEAN CONTROL, a FAULT-INJECTION (POSITIVE)
  CONTROL, and detector independence. This run has none of the three controls.
  It must not be cited as reverse-kernel correctness evidence, as sieve
  correctness evidence, or as coverage evidence, in any document, brief,
  submission or changelog.

  This is a statement about THIS ARTEFACT, not about the reverse kernels. The
  kernels are not being called wrong here — they are simply not evidenced by
  this file one way or the other.

  tests/phase6/known_answer_gate.py — the S172 bounded Phase 6 Miner

  It supplies precisely what this file lacks, for the four java_lcg variants
  including BOTH reverse variants (java_lcg_reverse, java_lcg_hybrid_reverse):
