- **Compare pointer.** At level `full` only, `compare_models_summary_latest.json` carries the diagnostics run id and

  archived sidecar can still point at the canonical path (Beta Q4). So it does not prove which checkpoint was graded.
- **WATCHER** passes the health check no run id (CD-07; `check_training_health(models_dir=...)` only).

No sound same-run binding exists without editing Step 5 or WATCHER. File times alone are not sound (a stale report and
a fresh checkpoint both look "recent"). **What a binding needs:** (a) WATCHER makes one run id per Step 5 run and
passes it to Step 5 (`--diagnostics-run-id`) and to the health check (`expected_run_id`) - CD-07; (b) Step 5 writes
that id at every diagnostics level, into each report and into each sidecar it saves; (c) Step 5 writes the sha256 of
the checkpoint it saved into the sidecar AND into the report that grades it; (d) for compare, the per-family archive
records that sha256 from the child's own output, not from a copy of the canonical dir. Then `_flagged_model` can
compare report id == sidecar id == expected id and report sha == sidecar sha == file sha.

### Item 5: the flag line

The flag line is written exactly as on `5f6c192` (`training_health_check.py:1307`). The unbound record is added only
to the RETURNED flag, after the write (`:1314`), and only when the caller passed `models_dir` (a new "not given"
default, `_MODELS_DIR_NOT_GIVEN`, `:129`, so an explicit None from WATCHER still gets the reason). No second line is
written, because binding never succeeds. **A second line would break an existing reader:** `read_flags` counts every
line of a flag id as a repeat and moves `last_flagged_at` (`why_report_flags.py:134-135`), so "flagged Nx" in the run
summary would be wrong. When a binding is built, it needs its own file or a line kind that `read_flags` skips. The
runner's latest-line-with-a-sha rule (`why_report_runner.py:202-216`) would read such a line; it is unchanged.

How each works, in plain words:

- **1.** A new agent starts with `_step5_output_dir = None`. When `run_step` runs Step 5, just before `EXEC CMD`, it
  keeps `final_params.get("output_dir")` (the dir Step 5 is told to write). The health check gets it as
  `models_dir`. If Step 5 did not run in this process, the value is None and the flag carries no model, as before.
  The value is passed as is (it may be relative, e.g. `models/reinforcement`); `training_health_check` makes it
  absolute against WATCHER's cwd. The Step 5 child is started with no `cwd=` (`agents/watcher_agent.py:2075`
  comment on 5f6c192), so it writes against the same cwd.
- **2.** `flagged_model` still takes the latest line that carries a sha. It now also counts the distinct shas the
  flag's lines named.
- **3.** Search order: walk-forward frozen dirs, then `--models-dir` (default: Step 6's dir), then the flag's
  recorded `models_dir`. In each models dir the sidecar's checkpoint is hashed on disk and must equal the flag's
  sha. A flag with no `models_dir` skips the last step. Not found anywhere: `no_checkpoint`, and the message lists
  all three places.
- **4.** `why_report_auto: "on"` with `why_report_wf_roots` `[]` or absent: ERROR log, runner not loaded, no
  notification, `auto_run` returns None.
